## P0: live output and report integrity

- [x] **P0-1 Missing data is UNKNOWN, not PASS** (`core/scoring.py`).
  `expected_roi_pct`, `valuation_excess_pct` and `excess_over_beta_hurdle_pct`
  pass their checks when `None`. Keep the hard filter result unchanged, but a
  candidate with an UNKNOWN critical check can be at most `WATCHLIST`, and the
  unknown checks are recorded (`unknown_checks`).
- [x] **P0-2 Remove the p² scenario weights** (`core/weight_optimizer.py`,
  `core/valuation_triangle.py`). P(bull)=p², P(base)=2p(1−p), P(bear)=(1−p)²
  treats the scenarios as two independent coin flips. `prob_up` never reaches
  the live target (all live payloads show base = 1.0), and the trend
  forecaster has no passing test. The target is the base fair value.
- [x] **P0-3 DCF weight 0 in the valuation triangle** (`config/weights.yaml`).
  Nominal TL FCF with a WACC of about 45% is dominated by terminal
  assumptions, and no test covers the DCF leg. DCF stays as a reference
  (`dcf_reference`). Legs with weight 0 are not listed in the method string.
- [x] **P0-4 Separate the tested rule from information in the reports**
  (Excel, email). The R0 rotation comes first and is labelled as the tested
  rule. Every other layer (labels, targets, entry bands, stops, effective
  bets, HRP, sector rotation, trend forecast, KAP panels) carries an
  "information only: not tested / test failed" label.
- [x] **P0-5 Regression guard: live score uses `weights.yaml` only.**
  A test fails if `score_candidates` uses optimised weights, regime weights,
  or a non-value weight above 0.
